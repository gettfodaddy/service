# VPN-бот и панели управления — тестовая версия

Это отдельный проект, не связанный с базой Bedolaga. Он содержит:

- Пользовательский бот: каталог тарифов, пробный доступ 1 день / 20 ГБ / 1 устройство, «Мой ключ», оплату через тестовый магазин ЮKassa, рефералов, бонусный баланс и тикеты поддержки.
- Telegram-раздел `/admin`: тарифы, сквады, тикеты и одноразовый код входа на сайт.
- Веб-панель администратора: тарифы, сквады, клиенты, заказы, тикеты, обзор, журнал изменений и редактор бота.
- Пробный тариф-черновик: 1 день, 20 ГБ, 1 устройство. Сначала нужно выбрать сквады, затем опубликовать.
- Общую базу данных для двух интерфейсов. Сайт доступен только администратору из `ADMIN_IDS`; вход по одноразовому коду, который выдаёт бот.

**Граница тестовой версии:** действующих клиентов Bedolaga не переносим. Инструкция подключения, отзывы и правила показывают текст-заготовку до заполнения ссылок. Для выдачи доступа нужен новый API-токен Remnawave с чтением сквадов и пользователей, созданием и обновлением пользователей, сбросом трафика. Для оплаты нужны тестовые `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `BOT_USERNAME` и публичный webhook. Не запускайте реальные продажи без проверки тестовых платежей, возвратов, выдачи доступа, кассы и миграций БД.

## Локальный запуск

1. Скопируйте `.env.example` в `.env`.
2. Заполните `BOT_TOKEN`, свой Telegram ID в `ADMIN_IDS`, длинный случайный `APP_SECRET`, URL и новый API-ключ Remnawave. Для покупки настройте также `BOT_USERNAME` и тестовые ключи ЮKassa. Не используйте токен Bedolaga или ранее опубликованный токен.
3. Для локального Docker задайте `POSTGRES_PASSWORD` и оставьте `COOKIE_SECURE=false`, затем запустите `docker compose up -d --build` из этой папки.
4. Откройте `/admin` в новом Telegram-боте → «Код для сайта».
5. Откройте локально `http://127.0.0.1:8000` и введите код.
6. В «Сквады» нажмите «Синхронизировать». Теперь можно создавать тарифы и назначать им сквады.

Веб-сервис в Docker слушает только `127.0.0.1:8000`. Для отдельного VPS, домена, HTTPS и Caddy используйте [инструкцию развёртывания](DEPLOY.md). На публичном домене установите точный `WEB_ORIGIN` и `COOKIE_SECURE=true`; порт `8000` наружу не открывайте.

## Редактор бота

Откройте веб-админку и раздел **Бот**. Там можно изменить название сервиса, приветствие и тексты основных экранов, подписи и значки всех кнопок пользовательского меню и внутренних действий, порядок и видимость восьми кнопок главного меню. Справа показывается предварительный вид главного меню. Нажмите **Сохранить изменения**; новые сообщения сразу используют сохранённые тексты, перезапуск бота не нужен. Уже отправленные сообщения в Telegram не меняются. Кнопка «Исходный вид» подготавливает значения по умолчанию, но применяет их только после сохранения.

Поля с переменными (`{subscription_url}`, `{price}` и т. д.) получают значения из заказа или Remnawave. Допустимые переменные подписаны под полем; неизвестные значения редактор не сохранит. Меняется только отображаемая подпись, действие кнопки остаётся прежним. Тарифы, сквады и цены редактируются в своих разделах.

## Данные и границы

- `tariffs` — название, описание, трафик, устройства, порядок и статус.
- `tariff_periods` — срок и цена в копейках.
- `tariff_squads` — выбранные UUID внутренних сквадов Remnawave.
- `squad_cache` — актуальный список сквадов; исчезнувшие сквады помечаются и видны в панели.
- `audit_events` — журнал действий администратора.
- `login_codes`, `web_sessions` — авторизация сайта.

Таблица `orders` фиксирует цену, параметры и сквады на момент покупки. Редактирование тарифа влияет только на будущие заказы и продления. Применение сквадов к уже активным подпискам остаётся отдельной будущей операцией.

## Перед полноценным запуском

1. Проверить интеграции на отдельном тестовом пользователе Remnawave и тестовом магазине ЮKassa.
2. Добавить управляемые миграции БД и сценарии возврата/отмены после успешной оплаты.
3. Заполнить инструкцию подключения, правила, отзывы и текст бренда.
4. Миграцию действующих клиентов с сохранением ссылок делать позже, после отдельной сверки с Bedolaga.

Перед рабочим запуском нужны миграции БД и резервное копирование. Текущий `create_all` подходит для новой тестовой базы.
